# SKILLS.md — moving the OpenCode setup to the Windows laptop

**Read this together with [`HANDOFF.md`](./HANDOFF.md).**

- `HANDOFF.md` moves the **project** — the code, the database, the `.env` files,
  the gates, the Windows traps.
- `SKILLS.md` (this file) moves the **agent** — the skills, subagents, commands
  and global config that made this machine able to run a council, drive a
  browser, tear down Blinkit, and follow Supabase/Postgres rules.

A fresh `git clone` gives you the code and **two** skills (the Supabase ones).
It does **not** give you `council`, the 57 `gstack-*` skills, or
`reverse-engineer-anything`. Those live in `~/.config/opencode/`, outside Git.
This file puts them back.

> **For the agent reading this on the new laptop:** you are being asked to
> rebuild a tool environment, not to change the grocery app. Do §2 (copy) or §3
> (rebuild), then run §4 to prove it worked. Do not edit anything under `apps/`,
> `supabase/` or `scripts/` while doing this.

## 2. Path A — copy the folder (recommended)

This is exact, keeps your Context7 key, and takes one minute.

**On the old machine (Linux):**

```bash
cd ~/.config
tar --exclude='opencode/node_modules' \
    --exclude='opencode/bun.lock' \
    -czf ~/opencode-config.tgz opencode
```

Carry `opencode-config.tgz` over USB or a password manager — **not** chat, email
or a commit. It contains your Context7 API key and `service.json`, which holds a
local password.

**On the Windows laptop (PowerShell):**

```powershell
# OpenCode must be closed while you do this.
$dest = "$env:USERPROFILE\.config\opencode"
New-Item -ItemType Directory -Force -Path $dest | Out-Null
tar -xzf "$env:USERPROFILE\Downloads\opencode-config.tgz" -C "$env:USERPROFILE\.config"
```

Then fix the one thing that is Linux-specific — `gstack` records the checkout it
was built from in `.source-path`, and its binaries are Linux ELF. On Windows:

```powershell
# Re-point gstack at a Windows checkout (see §3.4 for the clone), then:
cd C:\dev\gstack
bash ./setup --host opencode --global --prefix
```

Everything else in the folder is plain text and portable. Skip to §4.

> If you do **not** want to carry `service.json` (a local password) or the
> Context7 key, delete them from the tarball and follow §3.2 for the config.

## 3. Path B — rebuild from sources

### 3.1 Prerequisites

| Tool | Version | Why |
| --- | --- | --- |
| Node.js | **22 LTS** (REA needs ≥ 22.23.4 for its MCP; the app needs ≥ 20.19) | everything |
| npm | bundled with Node | `npx` |
| Git for Windows | any recent | gstack, REA |
| **Git Bash** | ships with Git for Windows | gstack's `./setup` is a bash script — PowerShell cannot run it |
| Bun | latest | gstack's setup/build tooling calls `bun` |
| Chrome/Chromium | any | gstack's browser skills; REA's website analysis |

### 3.2 Global config — `~/.config/opencode/`

Create `%USERPROFILE%\.config\opencode\opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "context7": {
      "type": "remote",
      "url": "https://mcp.context7.com/mcp",
      "enabled": true,
      "headers": {
        // Copy this key from the old machine's opencode.jsonc, or from
        // https://context7.com/dashboard. NEVER commit it to the repo.
        "Authorization": "Bearer <YOUR_CONTEXT7_API_KEY>"
      }
    }
  },
  "plugins": [
    "https://github.com/cnicolov/opencode-plugin-simple-memory"
  ]
}
```

And `%USERPROFILE%\.config\opencode\package.json`:

```json
{
  "dependencies": {
    "@opencode-ai/plugin": "1.17.7"
  }
}
```

`cli.json` is optional UI preference (diffs wrap, sidebar, animations). Copy it
from the old machine if you care; it holds no secrets.

**Do not copy `service.json`** — it is a local password and OpenCode regenerates
it.

### 3.4 gstack — 57 skills and 57 commands

gstack is installed **from a checkout**, not from a package. Run this in **Git
Bash**, not PowerShell:

```bash
mkdir -p /c/dev && cd /c/dev
git clone https://github.com/garrytan/gstack.git
cd gstack
git checkout v1.91.173.0     # the version this project was built against
./setup --host opencode --global --prefix
```

- `--host opencode` writes the OpenCode-shaped skills and commands.
- `--prefix` is what produces the `gstack-` names (`/gstack-review`,
  `/gstack-ship`, …). Without it you get short names (`/review`, `/ship`).
- `--global` lets this checkout own the global install.
- Check with `./setup --status`.

The browser-driven skills (`/browse`, `/qa`, `/scrape`, `/canary`, …) need a
Chromium build that `./setup` bootstraps. If you skipped it with `--no-browser`,
`bin/gstack-browser-ensure` installs it on first use.

> gstack is marked **experimental** for the OpenCode host by its own docs. If a
> skill misbehaves on Windows, that is the reason — not this project.

### 3.5 `reverse-engineer-anything` (REA)

Two independent things, and the skill alone is not enough:

```powershell
# 1. The skill (instructions only)
npx skills add https://github.com/morluto/rea --skill reverse-engineer-anything

# 2. The MCP server + matching instructions (what actually gives the agent tools)
npx rea-agents setup
```

`npx rea-agents setup` asks which agents to register and edits their config with
backups. Node must satisfy **≥ 22.23.4 / ≥ 24.22.1 / ≥ 26.12.1** or it refuses —
this exact version gate is why REA could not run on the old machine (Node
22.22.0). If you want REA's native-binary analysis you also need Hopper, Ghidra,
IDA or Kuna; **static JavaScript/Electron and website analysis need none**.

This project used REA's *evidence discipline* (and Chrome/CDP) rather than its
MCP, because of that version gate. `COMPETITOR-TEARDOWN.md` §9 records the
commands that were actually used.

## 4. Verify it worked

Restart OpenCode first — skills and agents are read at session start.

**From a shell:**

```powershell
$oc = "$env:USERPROFILE\.config\opencode"
"skills:   " + (Get-ChildItem "$oc\skills" -Directory).Count      # expect 60
"gstack-*: " + (Get-ChildItem "$oc\skills" -Directory -Filter 'gstack-*').Count  # expect 57
"commands: " + (Get-ChildItem "$oc\commands" -File).Count          # expect 58 (+ tamias if carried)
"agents:   " + (Get-ChildItem "$oc\agents" -File).Count            # expect 8
```

**From inside OpenCode**, in a fresh session in `C:\dev\eCommerce`, ask:

1. *"List the skills you can load."* → `council`, `gstack`, the `gstack-*`
   suite, `reverse-engineer-anything`, `supabase`,
   `supabase-postgres-best-practices` should all appear.
2. *"Which subagents can you spawn?"* → the eight `council-*` agents.
3. *"Use Context7 to look up the current Supabase RLS documentation."* → proves
   the MCP and its key.
4. *"What do you remember about this project?"* → proves the `simple-memory`
   plugin (expect little or nothing on a fresh install; that is normal).
5. *"Run /gstack-health."* → proves a gstack skill actually executes on Windows.

If 1 and 2 pass but 3 fails, the Context7 key is wrong. If 2 fails, the agent
frontmatter is malformed — `model:` names that do not exist are the usual cause.

## 6. Which skill to use for what in **this** project

| Situation | Skill / command |
| --- | --- |
| "Should we do X?" / "is this plan right?" / a costly fork | `council` (writes to `.council/runs/`, which is git-ignored) |
| Before writing a migration, RLS policy, index or SQL function | `supabase-postgres-best-practices` |
| Anything about Supabase products, auth, CLI, logs, Realtime | `supabase` |
| Reviewing a diff before merging | `/gstack-review` |
| Testing the app in a real browser and fixing what breaks | `/gstack-qa` (or `/gstack-qa-only` to report without fixing) |
| Ship / PR / version bump | `/gstack-ship`, then `/gstack-land-and-deploy` |
| Debugging "it was working yesterday" | `/gstack-investigate` |
| Design or visual polish | `/gstack-design-review`, `/gstack-plan-design-review` |
| Understanding how Blinkit/Zepto actually work | `reverse-engineer-anything` (see `COMPETITOR-TEARDOWN.md` §9 for the commands used here) |
| Code quality score across the repo | `/gstack-health` |
| A decision you already made and only want validated | none of these — just ask |

### 6.1 The one rule that outranks every skill

`AGENTS.md` is the law: **money in integer paise, two languages, RLS in Postgres,
no secrets in the client, every schema change with a migration and a test, and
`npm run typecheck && npm run lint && npm run test:db` before a step is called
done.** A skill that suggests otherwise is wrong for this repo.

### 6.2 Known inconsistencies (cosmetic, safe)

- The council agents mix two frontmatter styles: `permission:` (map, deprecated
  in OpenCode 2.x) on advisors `a`–`e`, and `permissions:` (ruleset array) on
  `council-advisor`, `council-reviewer`, `council-chairman`. **Both are enforced**;
  the schema accepts both. Unifying them is tidiness, not a security fix.
- The council skill body exists twice: `SKILL.md` at the repo root (committed)
  and `~/.config/opencode/skills/council/SKILL.md` (machine-local). The repo copy
  is the source of truth; the installed copy is what OpenCode loads.

## 7. Windows specifics

| Symptom | Cause | Fix |
| --- | --- | --- |
| `./setup: cannot execute binary file` or `bash: command not found` | gstack's setup is bash | Run it in **Git Bash** (`"C:\Program Files\Git\bin\bash.exe"`) |
| `bun: command not found` during gstack setup | gstack builds with Bun | `npm install -g bun` (or `winget install Oven-sh.Bun`) |
| `npx rea-agents setup` exits on the Node version | REA needs ≥ 22.23.4 | Upgrade Node 22 past that patch, or skip REA |
| A `council-*` subagent will not start | `model:` names a model this account does not have | Delete the `model:` line or point it at an available model |
| Skill not listed after installing | OpenCode reads skills at session start | Restart OpenCode |
| `npx skills add` installs into the repo, not the user profile | The skills CLI is project-scoped by default | That is correct here — `.agents/skills` is the committed, portable location |
| Browser skills fail with "no install found" | gstack checkout not registered | `cd C:\dev\gstack && bash ./setup --status`, then `--refresh-registered` |
